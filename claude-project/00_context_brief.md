## 콘텐츠 구조 (D21, docs/14 — 기준)
네 줄기 × 세 깊이 × 다섯 채널.
- 줄기: ① 뉴스 = 트렌디 체크(경제와 닿아 있는 재미있는 뉴스, 다섯 칸: 무슨 일 / 왜 눈길이 가나 / 경제와 닿는 지점 / **해석과 의미(가설)** / 더 볼 것. D22: 후보는 사실과 함께 가설 2~3개로 내고 Nick이 고름. 재료는 Google 트렌드 뜨는 검색어, 예약 작업 "트렌디 체크 후보"가 일~목 20:52에 후보를 냄) + 글로벌 체크 + 일정 체크 ② 엔진 = 아들러·플레처의 엔진 풀이(발표 뒤, 11월~)·엔진 가늠(발표 전, 규제 확인 뒤)·엔진 전망판(분기, 3·6·12개월 앞 지표 경로를 범위로, 1호 후보 12/9 FOMC 뒤) ③ 종목 체크 = 규칙이 만든 체크표 + 한 목소리의 읽기, 내 종목 ④ 사람과 과정 = 운영자 노트·고정관념 체크·장부·분기 심판·메이킹
- 깊이: 뉴스와 사람·과정은 전부 무료. 엔진은 무료(숫자와 한 줄)/기본(전문)/프로(전문 + 기록), 종목은 무료(Top 50 현재 상태)/기본(전 종목·과거 분포·내 종목 슬롯 소수)/프로(심화·슬롯 다수·주간 개인 묶음)
- 채널: SNS = 발견 / 유튜브 = 신뢰 / 레터 = 소유 / 메신저 = 속도(텔레그램 일방향 채널 11월, 카카오톡은 신고 수리 뒤 검토, 오픈채팅·그룹 금지) / 웹 = 조회
- 선: 종목 체크에 엔진 이름을 붙이지 않고 엔진의 종목 전망·평가는 하지 않는다 · 엔진의 해석은 표시를 달고 양쪽 경우(가운데 길 / 위 / 아래 / 무엇을 보면 알 수 있나)를 함께 쓰며 봉인된 범위에 묶는다 · 개인별 레터는 표준 카드의 조립(보유 수량·매수가를 받지 않음, 개인을 향한 문장 없음)이며 1332·변호사 답변 전에는 열지 않는다

## SNS 글의 방향 (D27, docs/05 §0)
독자가 가져갈 것에서 시작하고 공격적으로 쓴다. 첫 문장은 독자의 질문·고정관념과 숫자. 하지 않는 일, 만드는 방식, 방어 논리로 시작하지 않는다(10/6 첫 초안 20건이 이 이유로 전부 기각됐다). 네 가지 미끼: 고정관념 체크(주력 — 봇 연구 기록의 실제 숫자로 고정관념을 돌려 본 결과) / 오늘 밤·이번 주 체크 / 트렌디 체크 / 아들러 대 플레처. 편성 비율은 바로 써먹는 내용 70 · 레터와 도구 예고 20 · 만드는 과정 10. 조건과 한계는 셀프 답글에. 발행 문장에 "봉인"을 쓰지 않는다(풀어서: 발표 전에 저장해 두고, 바뀌면 드러나게 했다). 표현 기준은 `templates/copy_guide.md`와 voice_guide §7. 남는 선은 가격 방향·매매 권유·수익 약속·금지어·발표 전 엔진 답·실계좌 숫자뿐.

## 표현 방식 (D35, docs/16 v1.0 — 10/10 확정)

**채널별 형식(D36, 10/10)**: 스레드와 X는 같은 글 + 숫자가 있는 글에만 카드 한 장. 인스타는 카드뉴스 주 1벌 + 릴스 주 1편. 영상은 주 1편을 네 곳(쇼츠 · 릴스 · 스레드 · X)에 같은 파일로. X를 영상 중심으로 짜지 않는다.
글은 첫 덩어리만 줄 단위로 쓴다(문장은 자르지 않는다, 첫 덩어리는 한글 140자 안, 설명 문단은 그대로 — voice_guide §7-11). 이미지 카드는 코드가 그리는 1080×1350, 글자와 숫자만, 스레드 글에 한 장부터(첫 장 10/19 미국장 시간표. 첫 시험은 백테스트 숫자가 없는 글). 짧은 세로 타이포 영상은 창간 뒤 주 1편: 코드로 그린 글자 화면 + AI 음성(공개 모델 Supertonic 3, 같은 번호의 목소리를 계속 쓴다. "목소리는 AI 음성입니다"를 끝 화면과 설명란에, 인스타에는 AI 표시). 사람처럼 보이는 AI 인물은 만들지 않고 로고에 눈을 붙인 캐릭터를 감정 자리에만. 짧게 줄여 말맛을 낸 문장은 풀어 쓴다. 틀은 `assets/cards/` · `assets/video/` · `assets/character/`.

## 글이 만들어지는 구조 (D17, docs/11)
DB가 사실의 유일한 원천, 코드가 사실을 고르고, LLM은 그 사실로만 문장을 쓰고, 감정과 마지막 판단은 사람. 값은 알게 된 시각과 함께 쌓고 덮어쓰지 않는다. 뉴스의 중요도는 숫자가 정한다. 문장마다 근거 연결. 말투는 Nick의 글 표본과 수정 기록 기준(templates/voice_guide.md). 감정은 한 호에 한두 곳, 사람과 이미 일어난 일에만.

## 두 엔진 지표 예측 (D18, docs/12)
같은 자료를 두 엔진(각자 이름, 모델 회사 이름은 넣지 않음)에 주고 미국 경제지표의 발표값(CPI·고용·PCE·GDP, 보조로 PPI·주간 실업수당 청구)을 범위로 낸다. 발표 12시간 전까지 장부에 봉인, 발표 뒤 처음 발표값으로 채점, 기준선은 "직전 값 그대로". 가격·지수·환율·개별 실적·기준금리 결정은 예측하지 않는다. 과거 데이터로 성능을 재지 않고, 엔진이 낸 값은 사람이 고치지 않는다. 해자는 정확도가 아니라 봉인·채점 기록이며 정확도를 카피로 쓰지 않는다. **첫 봉인 목표 10/13. 연말까지는 발표가 끝난 뒤의 성적만 공개하고 발표 전 예측값은 발행물·SNS·영상 어디에도 싣지 않는다(D20). 준비 과정은 메이킹 형식으로 보여 줄 수 있다(레시피·API 키·실계좌·새 후보 종목명은 가림).** 엔진 이름은 **아들러(Claude 계열) / 플레처(GPT-6 Astra)**, 두 모델 모두 API 자동 호출(D19). Nick의 가설 "최신 모델 엔진은 시장 예상치만큼 맞히거나 곧 그렇게 된다, 그 기대감이 소구점"은 주장하지 않고 봉인 기록으로 가린다 — "AI가 기관보다 정확하다"는 기록 전에는 쓰지 않는다. 입력 자료 구조가 승부처(docs/13): 공공 통계를 알게 된 시각과 함께 쌓고 같은 사실 묶음을 두 엔진에 준다. 코드 `pipeline/forecast/`, `pipeline/collect/`. 공개 시점은 D20으로 확정.

## 운영 (D23·D24, docs/15)
Nick은 출장이 잦다. 운영은 PC가 아니라 서버(EC2)와 조종판(Google 시트)으로 한다. 서버가 수집·장부 봉인·엔진·초안 생성·게시를 하고, Nick은 휴대폰에서 시트의 문안을 고치고 "승인"만 한다. 승인되지 않은 글은 올라가지 않는다. 게시는 스레드(공식 API, 무료)와 X(종량제)부터, 게시 전에 금지어·본문 링크·길이를 검사한다. 장부는 한 곳에서만 쓴다(10/6 첫 봉인은 PC, 그 뒤 서버로). 코드 `pipeline/console/`, `pipeline/publish/`. **10/5 밤 서버에서 실제 가동**: 봇이 도는 기존 EC2의 별도 계정 `checksum`에서 게시 일꾼이 5분마다 돌고, 실제 시트·스레드·X로 시험 글 게시까지 확인했다. **원본은 깃허브 비공개 저장소 `romans0839-cpu/checksum`(D24)** — 세션이 저장소에 올리면 서버가 10분 안에 받아 자체 시험을 통과할 때만 쓰고, 결과는 시트 "오늘 현황"에 적힌다. PC 폴더는 사본. 장부·수집·엔진은 아직 서버로 옮기지 않았다.

**10/6**: 지표 수집도 서버에서 돈다(예약 작업 일꾼 `pipeline/console/jobs.py` — 매일 07:10과 노동통계국 발표 2분 뒤, 결과는 시트 "오늘 현황"). 세션이 저장소에 올린 SNS 초안 파일(`data/sns/drafts/*.md`)은 서버가 게시 대기열에 '초안'으로 싣는다. 서버 예약은 `scripts/server_cron.sh` 한 번으로 맞춘다.

**10/9**: 엔진 실행기(`pipeline/forecast/runner.py`)와 서버의 예약 작업 "엔진 봉인"이 있다(docs/12 §7-1·§7-2). 레시피는 서버에만 둔다(D34: 아들러 `claude-fable-5-1`, 플레처 `gpt-6-astra`, 쓰는 토큰에 상한). 서버가 발표 32시간 전(한국 시간 전날 13:30쯤)부터 20분마다 두 엔진을 불러 답을 모으고 장부에 봉인하며, 시트 "오늘 현황"의 "엔진 봉인" 줄에는 엔진별 상태만 적힌다(값은 없다). 장부 봉인도 서버가 한다(화요일, "장부 봉인" 줄).
