# 콘텐츠 구조 — 줄기 × 깊이 × 채널 (v1.1, 2026-10-05)

상태: **확정(D21, Nick 10/5). v1.1에서 트렌디 체크에 "해석과 의미" 칸을 더하고(D22) 만드는 순서(§9)를 붙였다.** 콘텐츠의 줄기·깊이·채널 편성은 이 문서가 기준이다. 사업 전체 그림은 docs/09 v1.3, 엔진은 docs/12, 채널 운영은 docs/05.
**2026-10-06 D27: SNS에서는 통념 체크를 주력으로 올리고 "만드는 중"을 주 1건 이하로 줄였다. SNS 글의 컨셉과 틀은 docs/05 §0이 기준이다.**
이 문서는 조사 기반 정리이며 법률 자문이 아니다.

## 0. 한 문장

**네 줄기의 콘텐츠를, 티어마다 깊이를 달리해, 채널마다 다른 모양으로 낸다.** 같은 재료를 한 번 만들어 여러 번 쓴다.

세 축
- **줄기**(무엇을): 뉴스 / 엔진 / 종목 체크 / 사람과 과정
- **깊이**(누구에게 어디까지): 무료 / 기본 / 프로
- **채널**(어떤 모양으로): SNS / 유튜브 / 레터 / 메신저 / 웹 도구

## 1. 네 줄기

| 줄기 | 무엇 | 역할 | 만드는 방식 |
|---|---|---|---|
| **① 뉴스** | 트렌디 체크(경제와 닿아 있는 요즘의 재미있는 뉴스) + 글로벌 체크 + 일정 체크 | 발견과 습관. 가볍게 들어오는 문 | 후보 자동 수집 → Nick이 고름 → 초안 자동 → 검수 |
| **② 엔진** | 아들러·플레처의 지표 예측, 발표 풀이, 경기 전망 | 전문성과 기대감. 다른 곳에 없는 것 | 엔진 자동 → 봉인 → 채점. 사람은 고치지 않고 표기만 검수 |
| **③ 종목 체크** | 종목별 체크표와 읽기, 내 종목 | 유료의 이유. 도구 | 규칙(코드) → 사실 → 문장 자동 → 검수 |
| **④ 사람과 과정** | 운영자 노트, 통념 체크, 장부, 분기 심판, 메이킹 | 신뢰와 온기. 반(反)리딩방의 증거 | Nick 직접 + 연구 기록에서 초안 |

### ① 뉴스 — 트렌디 체크 (재미있는 뉴스)

- 형식(한 건 다섯 칸, D22): **무슨 일** / **왜 눈길이 가나** / **경제와 닿는 지점**(사실과 숫자, 출처) / **해석과 의미**(운영자의 가설) / **더 볼 것**(출처 링크)
- **해석과 의미를 싣는다 (D22).** 내용만 옮기지 않고 "이게 무슨 뜻일 수 있나"를 가설로 쓴다. "제 가설은" 같은 표시를 달고, 산업·소비·정책·경기의 의미에 대해 쓴다. Claude는 후보마다 가설 2~3개를 함께 내고, 고르고 고치고 싣는 것은 Nick이다.
- 남는 선은 하나다: 특정 종목·가격의 방향, 매매 권유, 단정 표현은 쓰지 않는다(규제).
- 숫자는 1차 출처나 기사에서 인용하고 링크를 단다. 코드가 계산한 값이 아니므로 발행 전에 원문과 대조한다.
- 글로벌 체크와의 구분: 글로벌 체크는 일정표에 있던 발표와 큰 움직임을 다루고(중요도는 숫자가 정한다, D17), 트렌디 체크는 재미로 고른다.
- 제외 주제: 재난·인명 사고, 정치 공방, 연예 사생활.
- 고르는 법: Google 트렌드 "지금 뜨는 검색어"(한국·미국)에서 뜨는 것을 받고 → 제외 주제를 거르고 → "경제와 닿는 지점"이 있는 후보 5개를 사실·가설·초안과 함께 낸다 → Nick이 고른다. 기사는 제목과 링크만 쓰고 전문은 저장·전재하지 않는다.
- 운영: 지금은 Claude 예약 작업(일~목 저녁, 다음 날 아침 게시용). EC2로 옮길 때 수집기 코드(`pipeline/collect/trends.py`)와 텔레그램 승인으로 바꾼다.
- 자료 조건: Google 트렌드는 서비스 약관 아래 쓸 수 있고 재사용할 때 "자료: Google 트렌드"를 단다. 검색량은 어림값이다.
- 빈도: 레터에 주 2건, SNS에 평일 하루 1건.

### ② 엔진 — 세 가지 상품

| 이름 | 언제 | 내용 | 채점 |
|---|---|---|---|
| **엔진 풀이** (발표 뒤) | 핵심 발표 다음 날 아침 | 두 엔진이 본 값과 실제 값, 어디서 갈렸나(구성 항목), 각 엔진의 해석 3~4문장 | 발표값으로 즉시 |
| **엔진 가늠** (발표 전) | 핵심 발표 전날 | 두 엔진의 범위와 근거 | 발표값으로 |
| **엔진 전망판** (분기) | FOMC 경제전망이 나오는 달(3·6·9·12월) | 3·6·12개월 앞의 물가·실업률·성장률 경로를 범위로. 연준 전망과 나란히 | 시간이 지나며 |

- **경기 전망은 숫자로만 낸다.** "경기가 좋아진다"가 아니라 "6개월 뒤 실업률은 몇 %에서 몇 % 사이"처럼 통계로 채점되는 형태. 기준금리 결정, 주가·지수·환율, 개별 종목 실적은 계속 대상이 아니다. D18의 대상을 "다음 발표값"에서 "앞으로의 지표 경로"까지 넓혔다(D21).
- **해석은 붙이되 양쪽을 열어 둔다 (D21).** 숫자만으로는 읽을거리가 되지 않으므로 엔진의 해석을 함께 싣는다. 형식은 네 칸이다: **가운데 길**(범위의 가운데 값이 뜻하는 것) / **위로 벗어나는 경우** / **아래로 벗어나는 경우** / **무엇을 보면 알 수 있나**(다음 발표). 한쪽으로 단정하지 않는다. 해석은 봉인된 범위에 묶여 있어서, 다음 호에서 "어느 경우였나"를 되짚을 수 있다. 대상은 지표와 경기뿐이며 가격·종목·행동으로 잇지 않는다.
- **엔진 가늠(발표 전)은 규제 확인 뒤에만 연다.** 연말까지는 D20대로 엔진 풀이(발표 뒤)만 낸다.
- 엔진의 해석 문장은 "아들러의 해석", "플레처의 해석"으로 표시를 달고, 숫자는 사실 묶음에 있는 것만 쓴다(D17). 원인 단정과 가격 방향은 쓰지 않는다. 발행 전 Nick이 표기와 형식을 검수한다.
- 전망판 1호 후보: 12/9 FOMC(경제전망 포함) 직후.

### ③ 종목 체크 — 엔진 이름을 붙이지 않는다 (D21 확정: 가안)

| 안 | 내용 | 평가 |
|---|---|---|
| **가 (확정)** | 종목은 규칙이 만든 체크표 + 한 목소리의 읽기. 엔진 이름을 붙이지 않는다 | 엔진의 정체성이 "봉인하고 채점되는 예측"으로 깨끗하게 남는다 |
| 나 | 같은 체크표를 두 엔진이 각자 읽어 준다(프로 한정) | 재미는 있다. 그러나 둘의 말이 다르면 독자는 "누구 말을 믿고 사나"로 읽는다. 채점할 수 없다. 비용 2배 |
| 다 | 엔진이 종목의 전망·평가까지 한다 | 하지 않는다. 가격 예측이자 투자판단이라 규칙(D18)과 규제 모두에 걸린다 |

이유: 엔진은 채점되는 것만 말한다는 원칙을 지키면, 엔진의 말에는 성적표가 붙고 종목의 말에는 규칙이 붙는다. 독자가 두 가지를 헷갈리지 않는다.

종목 읽기(가안)의 내용: 상태가 바뀐 것, 과거 같은 상태의 분포(기저율), 다가오는 일정. 방향·권유는 쓰지 않는다. 종목 숫자는 데이터 표시 계약이 확정된 뒤에만 낸다(docs/10).

### ④ 사람과 과정

운영자 노트(화), 통념 체크(금), 장부 공개(금), 손글씨 한 장, 분기 심판, 메이킹(D20). 변경 없음.

## 2. 깊이 — 티어별로 어디까지

| 줄기 | 무료 | 기본 (월 1.5만) | 프로 (월 5.9만) |
|---|---|---|---|
| ① 트렌디 체크·글로벌 체크·일정 | 전부 | 전부 | 전부 |
| ② 엔진 풀이 (발표 뒤) | 숫자와 한 줄 | 전문: 구성 항목별 풀이, 두 엔진의 해석 | 전문 + 과거 기록 조회 |
| ② 엔진 가늠 (발표 전, 규제 확인 뒤) | — | 범위와 근거 | 범위와 근거 + 보조 지표까지 |
| ② 엔진 전망판 (분기) | 요약 한 장 | 전문 | 전문 + 지난 전망의 채점 이력 |
| ③ 종목 체크 | Top 50의 현재 상태 | 전 종목·ETF, 과거 분포, 상태 이력 | 심화: 조건 조합, 비교, 내 규칙 |
| ③ 내 종목 (개인별 레터) | — | 슬롯 소수 | 슬롯 다수 + 주간 개인 묶음 리포트 |
| ④ 통념 체크·장부·분기 심판 | 전부 | 전부 | + 연구 노트, 주간 모델 포트폴리오 |

- 무료는 넓게, 유료는 깊게(D13). 재미와 신뢰를 주는 줄기(①④)는 전부 무료로 두고, 전문성(②)과 도구(③)에서 깊이를 나눈다.
- 슬롯 수는 데이터 비용과 발송 비용을 산정한 뒤 정한다.

### 개인별 레터(내 종목)의 설계 — 맞춤 조언이 되지 않게

1. **종목 카드는 종목당 한 번만 만든다.** 같은 종목을 고른 사람은 모두 같은 카드를 받는다. 개인별 레터는 표준 카드의 조립이다.
2. **개인 사정을 묻지도 쓰지도 않는다.** 보유 수량, 매수가, 자산 규모, 투자 성향을 받지 않는다. 받는 것은 종목 기호뿐이다.
3. **개인을 향한 문장을 만들지 않는다.** "회원님은 ~하세요" 같은 문장은 없다. 카드에는 상태·분포·일정만 있다.
4. **질문에 답하지 않는다.** 슬롯 변경은 화면에서 직접 한다.
5. 구성: 화요일 본편 아래에 "내 종목 체크" 칸(슬롯 순서대로 카드) + 상태가 바뀐 날의 알림 한 줄.

이 설계가 유사투자자문업의 범위(불특정 다수에게 같은 내용) 안인지는 1332 질문 5번과 변호사 확인 항목이다. **답을 받기 전에는 열지 않는다.**

## 3. 채널 — 같은 재료, 다른 모양

| 줄기 | SNS (스레드 → X·인스타) | 유튜브 | 레터 (이메일) | 메신저 (텔레그램 채널) | 웹 도구 |
|---|---|---|---|---|---|
| ① 뉴스 (트렌디 체크) | 하루 1건, 4줄 | 쇼츠 주 1편 | 화요일 본편에 2건 + 글로벌 체크 3건 + 일정 | — | — |
| ② 엔진 풀이 | 발표 다음 날 "두 엔진과 실제" 한 장 | 월 1회 결산 롱폼(화면에서 성적표를 열어 설명), 발표 다음 날 쇼츠 | 발표 다음 날 아침 체크에 요약, 금요일에 성적 코너, 유료는 전문 | 발표 직후 숫자 한 줄(사실만) | 성적표 누적 |
| ② 엔진 전망판 | 요약 한 장 + 조각 3개 | 분기 롱폼 | 분기 특별호 | — | 전망과 채점 이력 |
| ③ 종목 체크 | 상태가 바뀐 Top 50 종목 수 같은 집계 한 줄 | 도구 사용법, 급락 체크 해설 | 화요일 본편, 유료는 내 종목 칸 | 급락 체크 알림, 프로 발행 알림 | 종목 체크 조회(중심) |
| ④ 사람과 과정 | **통념 체크(주력, 평일 거의 매일 — 연구 기록의 실제 숫자, D27)**, 만드는 중(주 1 이하, 재미있는 장면이 있을 때만) | 통념 체크 롱폼(주력), 분기 심판, 메이킹 쇼츠 | 운영자 노트, 통념 체크, 장부 | — | 장부 대조 |

- **SNS = 발견.** 가볍고 한 장으로 끝나는 것. 링크는 셀프 답글에만. 독자가 가져갈 것에서 시작하고, 믿음 쪽 이야기(기록·제작 방식)는 뒤로 둔다(D27, docs/05 §0).
- **유튜브 = 신뢰.** 과정을 보여 주고 길게 설명하는 것. PC 화면 + 목소리(D15).
- **레터 = 소유.** 정리된 본편. 유료의 깊이가 들어가는 곳.
- **메신저 = 속도.** 일방향 채널(댓글 끔)로 발표 직후 숫자와 알림만. 개인별 메신저 발송은 규제 확인 뒤에 검토하고, 오픈채팅·그룹은 쓰지 않는다.
  - **기본은 텔레그램 채널**(11월 개설).
  - **카카오톡은 신고 수리 뒤에 다시 본다.** 카카오 정책상 오픈채팅·그룹·1:1 방식의 투자 정보 제공은 금지이고("관리자만 말하기"도 예외가 아니라고 명시), 카카오톡 채널의 메시지 발송은 금융감독원에 등록·신고되지 않은 유사투자자문·주식 정보 제공 업종에 제한된다. 신고번호를 받은 뒤 카카오톡 채널 심사를 넣어 볼 수 있고, 메시지는 건당 요금이 든다(요금은 그때 확인).
- **웹 = 조회.** 쌓인 것을 찾아보는 곳.

| 분기 | 분기 심판 + 전망 체크 + 엔진 전망판 |

## 5. 여는 순서

## 6. 사람 손 — 평일 90분 안에 들어오는가 (어림)

| 일 | 빈도 | 한 번에 |
|---|---|---|
| 트렌디 체크 후보에서 고르기 + 검수 | 평일 매일 | 10분 |
| SNS 답글, 만드는 중 포스트 | 평일 매일 | 30분 |
| 아침 체크 검수 | 평일 매일 | 5분 |
| 화요일 본편 검수 + 운영자 노트 | 주 1회 | 40~50분 |
| 금요일 레터 검수 | 주 1회 | 30분 |
| 엔진 풀이 표기 검수 | 월 3~4회 | 10분 |
| 유튜브 | 주말 | 3시간 |

평일 기본 45분에 금요일은 75분, 화요일은 85~95분이 된다. 화요일이 상한에 걸린다. 그래서 트렌디 체크의 후보 고르기는 전날 밤 초안까지 자동으로 끝나 있어야 하고, 초안 자동화가 안 되는 코너는 열지 않는다(docs/09 §11).

## 7. 확정한 것 (D21, 10/5)

1. 이 구조(네 줄기 × 세 깊이 × 다섯 채널)로 간다
2. 종목 체크에 엔진 이름을 붙이지 않는다
3. 경기 전망을 엔진의 대상에 넣는다. 숫자(범위)로 내고, 양쪽이 열린 해석을 함께 싣는다. 분기 1회
4. 재미있는 뉴스 코너의 이름은 **트렌디 체크** (외래어 표기는 '트렌디')
5. 메신저 채널을 연다. 기본은 텔레그램, 카카오톡은 신고 수리 뒤 검토

## 8. 마지막 검토에서 고친 것과 남은 불확실성

고친 것
1. 처음에는 발표 전 예측을 유료의 중심으로 뒀다가, D20(연말까지 발표 뒤만)과 규제 확인 전이라는 점 때문에 "규제 확인 뒤"로 내렸다. 유료의 깊이는 엔진 풀이 전문과 종목 체크로 채운다.
2. 재미있는 뉴스가 "뉴스의 중요도는 숫자가 정한다"(D17)와 부딪히지 않게, 글로벌 체크와 코너를 나누고 쓰는 말을 구분했다.
3. 개인별 레터를 "개인별 분석"이 아니라 "표준 카드의 조립"으로 정의했다. 개인별로 문장을 새로 쓰는 설계는 맞춤 조언으로 읽힐 수 있어 뺐다.
4. 사람 손을 다시 더해 보니 화요일이 상한에 닿아, 코너를 여는 조건(초안 자동화)을 명시했다.

남은 불확실성
- 개인별 레터와 발표 전 예측 공개의 규제 해석(미확인) — 이 둘이 유료 차별화의 큰 부분이라 답에 따라 §2 표가 바뀐다
- 종목 줄기 전체가 데이터 표시 계약에 달려 있다(10/16 결정)
- 카카오톡 채널의 심사 기준과 건당 요금(신고 수리 뒤 확인)
- 엔진의 해석 문장 품질은 아직 본 적이 없다. 첫 봉인 뒤 실제 출력을 보고 "엔진 풀이"의 분량을 정한다
- 슬롯 수, 메신저 발송 비용, 개인별 발송 도구(스티비의 개인화로 되는지)는 산정 전
- 사람 손 시간은 어림이다. 창간 뒤 2주 실측으로 고친다

## 9. 만드는 순서 — 티어별 깊이 표(§2)의 순서대로

| 순서 | 줄 | 지금 상태 (10/5) | 다음에 만들 것 | 전제·기한 |
