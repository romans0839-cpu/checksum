# 지표 데이터 수집 구조 — MVP 설계 (v0.2, 2026-10-06)

상태: 1단계(노동통계국 한 줄기) 코드 작성·자체 시험 완료. **v0.2(10/6): 수집을 PC가 아니라 서버에서 돌린다(§8).** **실제 API로는 아직 돌려 보지 못했다** — 이 작업 환경에서는 통계기관 API에 접속할 수 없어, 서버에서 하는 첫 수집이 실제 시험이다.
관련: 엔진 설계 docs/12, 콘텐츠 DB 구조 docs/11, 결정 D18·D19. 코드 `pipeline/collect/`, `pipeline/forecast/bundle.py`.

## 0. 한 문장

**공공 통계를 "알게 된 시각"과 함께 쌓고, 엔진에게는 "그 시각까지 알려진 값"만으로 만든 같은 묶음을 준다.**
엔진의 정확도는 모델보다 입력에서 갈린다. 시장 예상치를 쓸 수 없는 우리에게는 이 구조가 승부처다.

## 1. 범위와 순서 — 얇게 끝까지

| 단계 | 만드는 것 | 닿는 발표 | 상태 |
|---|---|---|---|
| 1 | 노동통계국 수집기 → DB → 사실 묶음 | CPI(10/14), PPI(10/15), 고용보고서(11/6) | 코드·자체 시험 완료. 첫 실제 수집 대기 |
| 2 | 엔진 실행기(두 API 호출) → 레시피 v1 → 엔진 등록 → 첫 봉인 | 9월 CPI (10/13 봉인 목표) | 키 준비 뒤 |
| 3 | 경제분석국 수집기(PCE·GDP), 에너지정보청 주간 휘발유값 | GDP·PCE(10/29) | 10/27 전 |
| 4 | 노동부 주간 실업수당 청구, 재무부 금리, 발표 일정 자동 수집 | 주간 청구 | 11월 |
| 5 | EC2로 옮겨 발표 전날 봉인·다음 날 채점을 자동으로 | 전부 | 수집은 10/6에 옮김(§8). 봉인·채점은 10/19~ |

한 줄기(노동통계국 → CPI)를 수집부터 봉인까지 먼저 끝내고 옆으로 넓힌다. 콘텐츠 DB(docs/11)와 같은 DB·같은 규칙을 쓰므로, 여기서 쌓는 물가·고용 숫자는 글로벌 체크와 일정 체크의 사실로도 그대로 쓰인다.

## 2. 흐름

```
통계기관 API ──▶ 원문 보관(data/raw/) ──▶ 계열 제목 대조 ──▶ DB (수준값 + 파생값, 알게 된 시각)
                                                              │
                 발표 일정표 ──▶ 발표가 지난 대상의 "처음 발표값" 기록 (data/forecast/actuals.csv) ──▶ 채점
                                                              │
                                  자료 마감 시각 기준 사실 묶음 (해시) ──▶ 아들러 / 플레처 ──▶ 장부 봉인
```

## 3. 출처

모두 미국 연방 기관의 공공 통계다. 키는 무료이며 `.env`에만 둔다(`.env.example` 참고).

| 출처 | 받는 것 | 키 | 단계 |
|---|---|---|---|
| 노동통계국 (BLS) | CPI 17개(전 품목·근원과 구성 항목), 고용 6개, PPI 4개 — 한 번의 요청 | `BLS_API_KEY` (키가 있으면 하루 500회·계열 50개·20년, 제목과 계산값 제공) | 1 |
| 경제분석국 (BEA) | PCE 물가, 실질 GDP | `BEA_API_KEY` | 3 |
| 에너지정보청 (EIA) | 주간 휘발유 소매가 — 발표 전에 그 달 에너지 물가를 가늠하는 재료 | `EIA_API_KEY` | 3 |
| 노동부 (DOL) | 주간 신규 실업수당 청구 | 없음 | 4 |
| 재무부 | 일별 국채 금리 (콘텐츠 DB와 공용) | 없음 | 4 |

쓰지 않는 것: 시장 예상치(유료 집계), 민간 지표(ISM, 미시간대, ADP 등), 기사. 민간이 무료로 공개하는 지수(중고차 경매가, 임대료 지수 등)는 엔진 입력으로만 쓰더라도 약관을 확인한 뒤에 검토한다.

## 4. 저장 규칙

- **계열 이름**: `BLS.<계열 번호>`가 수준값, `.pc1`(전월비 %)·`.pc12`(전년비 %)·`.nc1`(전월 대비 증감)이 파생값. 목록은 `pipeline/collect/catalog.py`.
- **덮어쓰지 않는다**: 받은 값이 DB의 최신값과 같으면 넣지 않고, 다르면 새 줄로 쌓는다. 값마다 알게 된 시각이 남아 "그때 알려져 있던 숫자"를 되살릴 수 있다.
- **파생값 계산**: 전월비·전년비는 발표된 지수(받은 문자열 그대로)로 계산해 소수 1자리로 반올림한다. 노동통계국이 발표 수치를 만드는 방식과 같게 맞춘 것이며, API가 계산값을 함께 주면 대조해 다른 곳을 알린다.
- **빈 달**: 값이 비어 있는 달(조사가 없었던 달)은 건너뛰고, 그 달과 이어지는 파생값은 만들지 않는다.
- **제목 대조**: 계열 번호마다 API가 돌려주는 제목에 기대한 말이 있는지 본다. 맞지 않으면 '불일치'로 표시하고 사실 묶음에서 뺀다. 키가 없으면 제목이 오지 않아 '미확인'이 된다(키가 있어도 제목을 주지 않는 조사가 있을 수 있다 — 첫 수집에서 확인).
- **원문 보관**: 받은 응답을 `data/raw/bls/`에 그대로 두고 해시를 DB에 남긴다. 정리 과정에 오류가 있었으면 다시 풀 수 있다.

## 5. 처음 발표값

채점은 처음 발표된 값으로 한다(D18). 수집할 때마다 일정표에서 발표가 지난 대상을 찾아, 그 값을 **처음 알게 된 줄**을 `data/forecast/actuals.csv`에 덧붙인다. 한 번 적힌 줄은 고치지 않는다.
발표 뒤 20일을 넘겨 처음 받은 값은 수정치일 수 있어 자동으로 넣지 않고 알린다. 그래서 수집은 발표 다음 날 한 번은 돌아야 한다(EC2로 옮기면 자동).

## 6. 사실 묶음

`python -m pipeline.forecast.bundle --event CPI --ref 2026-09`

| 들어가는 것 | 내용 |
|---|---|
| 대상과 직전 값 | 맞혀야 할 지표, 단위, 발표 자릿수, 직전 발표값(기준선이 된다) |
| 과거 값 | 대상 지표의 최근 36개월 |
| 구성 항목 | 같은 발표의 세부 항목 최근 13개월 (CPI면 에너지·휘발유·식품·주거·자가주거비·임대료·중고차·신차·의류·의료·항공료·근원 상품·근원 서비스) |
| 관련 발표 | 이미 나와 있는 다른 발표 (CPI 묶음에는 PPI와 고용) |
| 전년비 재료 | 원계열 지수의 직전 달·작년 같은 달 수준, 같은 달의 과거 전월비 |
| 출처 표시 | 쓴 계열과 뺀 계열 |

- 자료 마감 시각까지 알려진 값만 넣는다. 같은 DB·같은 마감 시각이면 항상 같은 파일과 같은 해시가 나온다.
- 맞혀야 할 값은 넣지 않고, 이미 발표가 지났으면 묶음을 만들지 않는다.
- 묶음에는 형식 버전(`CPI/0.1`)이 있고 봉인 기록에 함께 남는다. 묶음에 넣는 자료를 바꾸는 것도 엔진을 바꾸는 것이므로, 형식을 고치면 버전을 올리고 엔진도 새 버전으로 등록한다.
- 묶음 파일은 `data/private/forecast/bundles/`에 둔다. 자료 자체는 공공 통계지만, 무엇을 골라 어떻게 주는지가 노하우다.

## 7. 정확도를 올리는 길 — 입력을 넓히는 순서

1. 주간 휘발유값(EIA) → 헤드라인 CPI의 에너지 몫. 가장 먼저 넣는다.
2. 주간 실업수당 청구(DOL) → 고용보고서.
3. 같은 달에 먼저 나오는 발표를 뒤 발표의 묶음에 넣기 (CPI·PPI → PCE 물가).
4. 재무부 금리, 수입물가.
5. 민간 공개 지수(약관 확인 뒤, 입력용으로만).

하나를 넣을 때마다 묶음 버전과 엔진 버전을 올리고, 도전자 버전으로 함께 봉인해 실시간 성적으로만 비교한다(D18 지킬 선 ②).

## 8. 운영

- **수집은 서버에서 돈다 (10/6).** 서버의 예약 작업 일꾼(`pipeline/console/jobs.py`, docs/15 §5-2)이 `collect()`를 부른다. PC에서 돌릴 일은 없다.
  - 매일 07:10(한국 시간): 밤사이 발표와 수정치를 받는다.
  - 노동통계국 발표(CPI·고용·PPI) 2분 뒤: 일정표(`data/forecast/schedule_*.csv`)에서 시각을 읽는다. 발표값이 아직 올라오지 않았으면 10분마다 다시 받고(3시간 안), 처음 발표값이 `actuals.csv`에 적히면 끝낸다. 서머타임이 끝나 발표 시각이 바뀌어도 일정표를 따라간다.
  - 결과는 조종판 "오늘 현황"의 "지표 수집" 줄에 적힌다. 제목이 맞지 않는 계열은 API가 돌려준 제목과 함께 메모 칸에 적힌다.
- **기록은 서버 한 곳에만 쌓는다.** DB(`data/db/`), 원문(`data/raw/bls/`), 처음 발표값(`data/forecast/actuals.csv`)은 서버의 저장소 폴더 안, 저장소가 추적하지 않는 자리에 있다. "알게 된 시각"은 서버가 처음 받은 때부터 쌓인다. PC의 `collect_indicators.bat`은 저장하지 않는 확인용(`--dry-run`)으로 바꿨다.
- **키**: 서버의 `~/checksum/.env`에 `BLS_API_KEY`가 있어야 한다. 없으면 "실패: 서버 .env 에 BLS_API_KEY 가 없음"으로 적히고, 넣으면 한 시간 안에 다시 시도한다.
- **실패**: API에 닿지 못하면 아무것도 쓰지 않고 끝나고, 정해진 간격으로 다시 시도한다.
- **확인 명령**: `python -m pipeline.console.jobs plan`(앞으로 8일의 예정), `python -m pipeline.console.jobs run collect_indicators`(지금 한 번), `python -m pipeline.collect.bls --dry-run`(저장 없이 계열별 제목 대조와 최신 달 표시), `python -m pipeline.collect.selftest`(인터넷 없이 구조 점검).

## 9. Nick이 할 일 (서버에서 한 번, 3분)

1. 서버의 `checksum` 계정에서 `cd ~/checksum && git pull && bash scripts/server_cron.sh` — 예약 세 줄을 맞추고 지표 수집을 한 번 돌려 화면에 보여 준다
2. 화면에 "[할 일] 서버 .env 에 BLS_API_KEY 가 없습니다"가 나오면, PC `.env`의 `BLS_API_KEY=` 줄을 서버의 `~/checksum/.env`에 그대로 한 줄 넣고 1번을 다시 돌린다 (키 값은 채팅에 붙이지 않는다)
3. "저장: 새 값 …"과 "가장 최근 달"이 나오면 된 것이다. [주의]나 "실패" 줄이 나오면 그대로 알려 주기. 그 뒤로는 조종판 "오늘 현황"의 "지표 수집" 줄만 보면 된다
4. BEA·EIA 키는 3단계 수집기를 만들 때 같은 `.env`에 넣는다

## 10. 마지막 검토에서 고친 것과 남은 불확실성

고친 것
1. 전월비를 API의 계산값에 의존하려던 것을, 발표 지수로 직접 계산하고 API 값은 대조용으로만 쓰게 바꿨다. 키가 없거나 계산값이 오지 않아도 같은 숫자가 나온다.
2. 반올림을 파이썬 기본(짝수 쪽 반올림)이 아니라 사사오입으로 고쳤다. 0.25가 0.2가 아니라 0.3이 된다.
3. 계열 번호를 믿지 않고 제목과 대조하게 했다. 번호 하나가 틀려도 엉뚱한 계열이 묶음에 들어가지 않는다.
4. 발표 뒤 늦게 받은 값이 "처음 발표값"으로 잘못 기록되지 않게 20일 기준을 넣었다.
5. 묶음에 형식 버전을 넣고 봉인 기록까지 이어지게 했다.

10/6 서버로 옮기면서 (v0.2): 수집을 `collect()`로 묶어 요약을 돌려주게 했고, 오류 문구와 원문에 키가 섞이지 않게 가렸다. 발표 직후 수집은 "처음 발표값이 적혔는가"로 끝을 판단한다.

남은 불확실성
- **실제 API 응답으로 시험하지 못했다.** 응답 모양은 공식 문서 기준으로 맞췄다. 첫 수집 결과를 보고 고칠 수 있다
- 노동통계국 API가 발표 시각에 바로 갱신되는지는 확인하지 못했다. 그래서 2분 뒤에 받고 10분마다 다시 받게 했다. 실제 지연은 10/14 CPI에서 처음 본다
- 서버의 DB와 `actuals.csv`는 아직 백업하지 않는다. 첫 봉인(10/13) 전에 백업 작업을 더한다
- 계열 번호 27개 가운데 구성 항목 번호 일부는 기억에 의존했다. 첫 수집의 제목 대조가 걸러 준다
- 2025년 10월은 정부 업무 중단으로 CPI 값이 비어 있을 수 있다. 그러면 2026년 10월 전년비(11/10 발표)가 어떻게 발표되는지 확인이 필요하다. 발표되지 않으면 그 대상은 채점하지 않는다
- 묶음이 지금 형식(JSON)으로는 1만 토큰 안팎이다. 엔진에 줄 때는 실행기가 표로 바꿔 넘긴다(`runner.py`의 `table/1`, 10/9 — 시험 자료로 5천 자쯤)
- BEA·EIA·DOL 수집기는 아직 없다(만들면 예약 작업 일꾼의 작업표에 더한다)
