# 콘텐츠 시스템 구조 (v0.2, 2026-10-05)

상태: 구조 확정(D17). 구현은 §7 순서대로. 표 정의는 `pipeline/db/schema.sql`, 말투·감정 규칙은 `templates/voice_guide.md`.
v0.1(10/5 대화에서 제안) → v0.2: 자체 검토에서 9건을 고쳤다(§8).

## 0. 한 문장

**DB가 사실의 유일한 원천이고, 코드가 사실을 고르고, LLM은 그 사실로만 문장을 쓰고, 감정과 마지막 판단은 사람이 맡는다.**

## 1. 흐름

```
수집(일정·숫자·발표문) → 원자료 보관 → 정리(일정 / 시계열 / 문서)
   → 큰 움직임 판정(숫자가 중요도를 정함) → 사실 생성(코드) → 이번 호 사실 묶음
   → 초안(LLM, 묶음 안의 사실만) → 검사(코드) → 말투 다듬기 + 감정 후보(LLM)
   → 검수·감정 선택·승인(사람) → 발행 → 문장별 근거와 수정 내용 기록
   → 13주 뒤 판정 채점
```

## 2. 저장 구조 (SQLite 파일 하나, 표 25개 — 10/5 엔진 예측 표 4개와 뜨는 검색어 표 1개 추가)

| 묶음 | 표 | 담는 것 |
|---|---|---|
| 출처 | source | 출처별 발행 권리(공공 / 출처 표기 / 표시 계약 / 링크만 / 내부용 / 미확인)와 표기 문구 |
| 원자료 | raw_fetch | 언제 어디서 무엇을 받았는지, 파일 위치와 해시. 원자료 파일은 `data/raw/` |
| 숫자 | series, observation | 금리·환율·지표. 값마다 "알게 된 시각"을 남기고 덮어쓰지 않는다 |
| 일정 | event, event_value | FOMC·물가·고용·어닝·휴장. 발표 결과·직전치·수정치 |
| 문서 | document, doc_link | 1차 발표문과 기사의 제목·링크·자체 요약. 인도적 사안 표시 |
| 움직임 | market_move | 그날 변동이 과거 분포의 몇 번째인지 |
| 사실 | fact | LLM이 볼 수 있는 유일한 재료. 코드가 만든 한 줄 문장 + 근거 + 발행 가능 여부 |
| 판정 | judgment, score | 규칙이 내린 상태 판정과 13주 뒤 채점. 장부 번호와 연결 |
| 발행 | issue, issue_sentence, correction | 호별 초안·최종본, 문장별 등급과 근거, 정정 기록 |
| 말투 | edit_log, phrase_log | 검수에서 고친 문장, 이미 쓴 인사·감정 표현 |
| 엔진 예측 | engine_version, forecast_target, forecast, forecast_score | 엔진 버전, 대상 지표, 봉인된 예측과 채점(D18, docs/12). 원문의 기준은 장부이고 이 표는 조회용 사본 |
| 운영 | job, job_run, meta | 작업 일정과 실행 결과 |

넣지 않는 것: 계좌 금액·수량·수익률(D3), 벤더 가격 원자료(가격 이력은 파일로 따로 두고 DB에는 파생 상태와 사실만), 말투 표본 메일(`data/private/voice/` 파일로만).

## 3. 설계 원칙 다섯 가지

1. **덮어쓰지 않는다.** 지표는 나중에 수정된다. 값마다 알게 된 시각을 남겨 "그때 시장이 본 숫자"를 되살릴 수 있게 한다. 전망 체크·채점·정정의 전제다.
2. **출처마다 발행 권리를 적는다.** 사실의 발행 가능 여부는 출처에서 자동으로 정해지고, 권리가 없거나 미확인인 사실이 섞이면 발행이 막힌다. 현재 미확인: 한국은행, 예탁결제원, 가격 벤더.
3. **중요도는 숫자가 정한다.** "영향을 미칠 만한 뉴스"를 헤드라인으로 고르지 않는다. 일정표에 있던 발표이거나 금리·환율·지수가 과거 분포에서 크게 움직인 날에만 문서를 붙인다. 문서는 원인이 아니라 "같은 날 있었던 일"로 연결한다.
4. **LLM은 사실 표만 본다.** 원자료·기사 원문·DB 전체를 주지 않는다. 숫자는 코드가 만든 문장에 이미 들어 있고, LLM은 고르고 잇고 풀어 쓴다.
5. **문장마다 근거를 연결한다.** 발행된 문장은 등급(사실 / 판정 / 맥락 / 감정 / 운영자 노트)과 근거 사실 번호를 갖는다. 정정이 생기면 어느 호 어느 문장이 영향받았는지 바로 나온다. 나중에 "문장을 누르면 출처가 보이는" 기능의 바탕이 된다.

## 4. 글이 만들어지는 여섯 단계

1. **사실 묶음** (코드): 이번 호 슬롯별로 쓸 사실을 고른다. 묵은 데이터와 발행 권리 없는 사실은 빠진다.
2. **초안** (LLM): 묶음 안의 사실만 쓴다. 사실·판정 문장에는 사실 번호를 단다. 배경 설명(맥락)은 쓸 수 있지만 숫자·날짜·고유명사가 들어가면 묶음에 있어야 한다.
3. **검사** (코드): 묶음에 없는 숫자·고유명사, 금지어, 예측·단정·원인 단정 표현, 근거 없는 사실 문장을 잡아 발행을 막는다.
4. **말투와 감정** (LLM): 말투 지침과 최근 수정 기록에 맞춰 다듬고, 감정 문장 후보를 2~3개 낸다. 최근 8주에 쓴 표현은 피한다.
5. **검수·승인** (사람): 초안과 근거를 나란히 보고 고친다. 감정 문장은 Nick이 고르거나 직접 쓰거나 뺀다. 운영자 노트는 직접 쓴다. 텔레그램으로 초안을 받고 승인·보류.
6. **기록** (코드): 최종본, 문장별 근거, 고친 내용, 쓴 표현을 남긴다. 고친 내용이 다음 초안의 말투 기준이 된다.

LLM이 실패하면 사실 문장만으로 발행한다. 아침 체크는 처음 2주는 승인 후 발송, 그 뒤 검사만 통과하면 자동 발송을 검토한다.

## 5. 말투와 감정

- 말투 기준은 Nick의 글 표본(보고메일)에서 뽑고, 검수에서 고친 문장으로 계속 맞춘다. 표본은 회사 내용을 가린 뒤 `data/private/voice/`에만 둔다.
- 감정은 한 호에 한두 곳. **사람과 이미 일어난 일에만 붙이고, 가격 방향이나 행동 권유와 섞지 않는다.** 종류는 걱정·응원·궁금함·안도·사과·연대 여섯 가지.
- 감정을 켜는 조건은 데이터에서 온다: 급락 체크가 발동한 주, 서학개미 보유 상위 종목이 크게 움직인 주, 인도적 사안으로 표시된 문서가 있는 주, 정정이 있는 호.
- 감정 문장은 LLM이 후보를 내고 사람이 고른다. Nick이 실제로 그렇게 느끼지 않으면 쓰지 않는다. 0개인 호도 있다.

## 6. 운영

- **어디서**: 항상 켜져 있는 EC2. 봇과 리눅스 계정·가상환경을 나누고 봇의 키 파일에 접근하지 못하게 한다. 수집한 웹 문서는 믿을 수 없는 입력이므로, 문서를 읽는 LLM 단계는 요약만 하고 다른 동작을 일으키지 못하게 한다.
- **시간**: 11/1부터 미국 서머타임이 끝나 미국장 마감이 한국 시간 06:00이 된다. 06:30 아침 체크는 빠듯하다 → 겨울철 발송 시각을 07:00 전후로 옮기는 것을 검토. 공식 금리 자료의 게시 시각도 확인 후 수집 시각을 정한다.
- **실패**: 수집이 실패하면 그 사실만 빠진다. 발행을 막아야 하는 작업(금리, 일정, 봇 신호)이 실패하면 그 호를 보류하고 텔레그램으로 알린다.
- **장부**: 지금은 `ledger_commit.bat` 수동 실행. 2주차에 EC2에서 화요일 오전 자동 봉인으로 옮긴다.
- **백업**: DB 파일과 `data/private/`를 매일 다른 곳에 복사.
- **시험**: 과거 호 몇 개를 기준 묶음으로 두고, 프롬프트나 말투 지침을 바꿀 때마다 다시 돌려 비교한다.

## 8. 마지막 검토에서 고친 것 (v0.1 → v0.2)

1. 원자료를 따로 보관한다. 정리 과정의 오류를 나중에 다시 풀 수 있다.
2. 사실 묶음을 그때그때 만들고 버리는 대신 "사실" 표로 남긴다. 어떤 사실이 어느 호 어느 문장에 쓰였는지 추적하기 위해서다.
3. 문장별 등급과 근거를 남긴다. 정정 범위 추적과 문장별 출처 표시가 가능해진다.
4. 검수에서 고친 내용을 기록해 말투 기준으로 되먹인다.
5. 이미 쓴 인사·감정 표현을 기록해 반복을 막는다. 매주 같은 맺음말은 기계가 쓴 티가 가장 나는 곳이다.
6. 같은 값으로 되돌아가는 재수정도 보존하도록 숫자 표의 중복 기준을 바꿨다.
7. 말투 표본(회사 메일)은 DB에 넣지 않고 비공개 폴더의 파일로만 둔다.
8. 수집 문서를 통한 조작 위험과 봇 키 분리를 운영 원칙에 넣었다.
9. 겨울철 미국장 마감 시각 문제를 일정에 반영했다.

남은 불확실성: 공식 금리 자료의 게시 시각(미확인) · 한국은행과 예탁결제원 자료의 이용 조건(미확인) · 시장 예상치는 대개 유료 자료라 당분간 쓰지 못한다(엔진 예측의 내부 비교에만 쓴다 — docs/12)("시장이 이미 알던 것"은 연준의 기존 발표와 점도표로 쓴다) · 지수·종목의 큰 움직임 판정은 가격 데이터 라이선스 뒤에 가능 · LLM 호출 비용(미산정) · Windows 마운트 폴더에서의 DB 동작은 시험하지 않았다(리눅스에서 생성·제약·시점 조회 시험 통과).

## 9. 하지 않는 것

LLM에게 중요도 판단이나 판정을 맡기는 것 / 기사 전문 저장·전재 / 감정 문장의 자동 발행 / 가격 방향에 감정을 붙이는 것 / 봇과 같은 계정·키로 돌리는 것.
