# 타이포 영상 — 코드로 그린 글자 (1080×1920)

상태: **목소리 없이 간다(D38, 2026-10-10). 스레드 · X · 인스타에는 소리 없는 파일, 유튜브 쇼츠에만 음악을 얹은 파일.** 창간(10/20) 뒤 주 1편. 근거와 위험은 `docs/16_expression_formats.md` §4. 롱폼(화면 녹화 + 본인 목소리, D15)은 따로다.

| 파일 | 내용 |
|---|---|
| `<이름>.html` | 장면 설계. `render(t)`에 시각(초)을 넣으면 그 순간의 그림이 정해진다. 장면의 길이는 파일 안의 `S`(초)로 정한다 |
| `render.py` | HTML → MP4. 브라우저로 한 장씩 찍어 ffmpeg 로 묶는다. `--audio`로 음악을 얹는다 |
| `music/` | 유튜브에 얹을 음악. **유튜브 스튜디오의 오디오 보관함에서 Nick이 고른 곡만** 둔다(곡 이름과 받은 날을 `music/README.md`에 적는다) |
| `samples/leverage_math.mp4` | 시안 32.1초 (3배 레버리지, 소리 없음) |
| `voice.py`, `<이름>.voice.json` | **쓰지 않는다(D38).** AI 음성과 장면 시각표를 만들던 도구. 본인 목소리를 얹게 되면 시각표 부분을 다시 쓴다 |

```
python assets/video/render.py assets/video/leverage_math.html                  # 소리 없는 판
python assets/video/render.py assets/video/leverage_math.html --audio assets/video/music/<곡>.mp3 --out assets/video/samples/leverage_math_yt.mp4   # 유튜브용
python assets/video/render.py assets/video/leverage_math.html --stills 1.6,9.0,24.5   # 장면 확인용 그림
```
글꼴은 `assets/cards/`에서 `npm install` 한 것을 쓴다. 브라우저와 ffmpeg가 있어야 한다(서버에는 없다 — 세션이 만든다).

## 새 영상을 만들 때
1. 글을 고른다. 다섯 종목에 닿는 것부터(D37): 계산 예시 · 상품의 구조 · 일정처럼 백테스트 숫자가 없는 글로(docs/16 §3)
2. 화면의 글을 쓴다: 40초 안, 첫 장면에 독자가 가져갈 것, `templates/copy_guide.md` 문체
3. HTML의 장면을 나눈다. `leverage_math.html`을 본으로 삼는다. **소리가 없으므로 읽는 속도가 장면의 길이를 정한다 — 한 장면의 글자 수를 초당 6 ~ 8자로**(넷플릭스 한국어 자막 기준 초당 12자보다 느리게, docs/research)
4. `render.py`로 만들고, 그림 몇 장을 뽑아 글자가 넘치지 않는지 본다

## 지킬 것
- 글자는 릴스 · 쇼츠의 화면 단추에 가리지 않는 자리(위 270px, 아래 670px, 양옆 65px 밖)에만 둔다
- 핵심 숫자는 처음 4 ~ 5초 안에. 첫 문장을 단정으로 쓰지 않는다(계산 예시면 "…라면"의 조건문)
- 끝 화면에 "계산 예시" 같은 조건과 고지를 넣는다. 가격 차트는 그리지 않는다(D26). 스톡 영상 · 아바타 · 사람처럼 보이는 AI 인물 · AI 음성은 쓰지 않는다
- 영상마다 질문과 자료가 달라야 한다. 유튜브는 해설이 거의 없는 "흘러가는 글자" 영상과 틀이 같은 영상을 수익 창출에서 뺀다(수익 창출 자격의 규칙이고, 올리지 못하게 하는 규칙은 아니다)
- 음악은 유튜브에 올리는 파일에만 얹는다. 오디오 보관함의 곡은 유튜브 영상에 쓰도록 제공되는 것이라 다른 곳에 올리는 파일에는 넣지 않는다(이용 조건은 곡을 받을 때 화면에서 확인한다)
